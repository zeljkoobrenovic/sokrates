How it works

  • Tasks come from the commits. Commits that mention the same ticket id (e.g. ABC-123) are one task. Otherwise a task is consecutive commits by the same author, at most a day apart, touching overlapping files (the history has dates, not times). Tasks are split into sessions of at most 10 files or 400 changed lines.
  • Scopes: main, test, build & deployment and other code count; generated code, files in no scope and files with extensions the analysis does not cover are left out.
  • Reads use the current total lines of the edited files, comments and blank lines included (at most 2,000 lines per file), times a read amplification for re-reads and unchanged neighbouring files, plus exploration reads per session. New files are written, not read; deleted files cost nothing.
  • Writes come from the churn: an edit to an existing file costs more per line (the edit repeats the old text and some context) than a line in a new file.
  • Agent steps are a base number plus a number per touched file. Every step sends the whole context again; most of it is a cache read, a share is a cache miss. Tool output and reasoning are added per step.
  • Task type comes from the shape of the task: new code (most lines in new files), refactoring (broad, deletes about as much as it adds), fix (at most 60 lines in at most 3 files) or feature (the rest). It sets the read amplification.
  • Still priors: tool output, reasoning, cache misses and non-coding sessions. Git cannot see the agent's behaviour, so the result is a range (P10–P90 of simulations), not a measurement.
  • Left out as noise:
  • Smell test: the cost per developer-day compares with the reference you set (by default the about $13 per developer per active day reported for Claude Code in enterprises). Open-source histories with many drive-by contributors land far lower; a large gap for a company team means the priors need a look, or that agent-assisted developers do more per day than the history shows.
  • Calibrate with a replay pilot: pick 20–30 tasks from the CSV across types and sizes, check out the parent of each task's first commit (git checkout <first_sha>^), give an agent the commit message or ticket text as the prompt, record what each session actually used, and compare with the task's estimate. Then adjust the priors above.
