What the history would have cost an AI coding agent: commits become tasks and sessions, and every step of a session re-sends the growing context.

What an AI coding agent would spend to write the main code again the way a good team works: small commits with tests, fixes, refactoring, and redoing what the uncertainty says will miss.

Base AI costs: the agent's tokens only, without people's time, discovery, planning, review, integration or infrastructure. Not a budget. Token counts come first; the greyed-out costs are indicative, as they depend on the model, product and hosting (see the prices in Assumptions).

How it works

  • Measured: only the lines of main code (); everything else is assumed.
  • Uncertainty: how likely the built work delivers the intended value. Low is a migration; higher levels redo a share p of it (changed, discarded, rebuilt), so kept code ÷ (1 − p) gets built. The history's share in hindsight: 1 − lines today ÷ lines added.
  • Building: commit-sized sessions write code and tests, reading nearby code.
  • Fixing: fixes per 1,000 lines built, each a small change in about 2 files after reading for the cause; steps × debugging.
  • Refactoring: a share of the kept code is rewritten, reading twice what changes.
  • Sessions use the Historical session model.
  • A range, not a measurement: P10–P90 of simulations.
  • Core: a session costs about steps × average context, mostly at cache prices, plus its output.
  • Tasks: commits sharing a ticket id (e.g. ABC-123) form a task; otherwise, overlapping commits of one author at most a day apart. Tasks split into sessions of at most 10 files or 400 changed lines.
  • Scopes: main, test, build & deployment and other code count; generated, unscoped and unanalyzed files do not.
  • Steps: per session plus per touched file; fix tasks × debugging, for the reproduce, run and inspect loops git does not show.
  • Context: base context plus reads, tool output and output. Reads: the edited files' total lines (at most 2,000 each) × tokens per line × amplification. New files are written, not read; deleted files are free.
  • Output: changed lines × tokens per line × write overhead, plus output per step.
  • Cost: new context at the cache-write price, re-sent context at the cache-read price (misses at the input price), output at the output price.
  • Task type groups the results: new code (mostly new files), refactoring (broad, deletes about as much as it adds), fix (at most 60 lines in 3 files), feature (the rest). Only fixes change the model.
  • A range, not a measurement: git cannot see the agent, so steps, tool output, output per step and cache misses are assumed; results are P10–P90 of simulations. Steps and cache misses matter most.
  • Left out as noise:
  • Smell test: compare the cost per developer-day with the reference (default about $13, the reported enterprise average for Claude Code). Open-source histories land far lower; a big gap for a company team means checking the assumptions, or that agents let developers do more per day.
  • Calibrate: replay 20–30 varied tasks from the CSV: check out each parent commit (git checkout <first_sha>^), prompt an agent with the commit message or ticket, record its usage, compare, and adjust the assumptions.
